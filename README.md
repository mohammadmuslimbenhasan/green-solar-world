# Green Solar World Inc. — Wholesale Electrical & Lighting

Dynamic, Supabase-backed re-creation of gsworld.ca built with **Next.js 15 (App Router) + TypeScript + Tailwind CSS 4**. Catalog pages use **ISR (`revalidate = 300`)** — effectively instant, always fresh. Includes a full **admin panel** (`/admin`) and **customer portal** (`/account`) on top of Supabase Auth + RLS.

## Quick start

```bash
npm install
npm run dev        # http://localhost:3000
```

The site works fully with **no environment variables** — the catalog is bundled in `data/catalog.ts` and every Supabase read falls back to bundled data, so builds never break.

## Build

```bash
npm run build      # type-checks, lints, prerenders (92 pages) + ISR
npm run start      # production server
```

Verified: build passes with **zero env vars** and with **dummy env vars** (`NEXT_PUBLIC_SUPABASE_URL=https://example.supabase.co`, `NEXT_PUBLIC_SUPABASE_ANON_KEY=dummy` — fetch fails → bundled fallback).

## Admin panel (`/admin`)

Server-side role guard first: every `/admin` layout render reads `profiles.role` via the cookie-bound Supabase client — unauthenticated → redirect `/login?next=/admin`, non-admin → styled 403, and every mutation route under `/api/admin/*` re-checks the role server-side (never trusts the client). When Supabase isn't configured, admin pages render a "Database not configured" empty state and the build stays green.

| Page | What it does |
|---|---|
| `/admin` | Dashboard: stat cards (products, orders by status, new inquiries, live reviews, customers), recent orders + inquiries, quick links |
| `/admin/products` | Search + collection/category filter, stock/featured badges, edit/delete (two-step confirm) |
| `/admin/products/new` · `/admin/products/[id]` | Full form: name, auto-slug (editable), SKU, category (collection derived), prices, stock, featured, short/long descriptions, spec-bullet editor, FAQ editor, meta title/description with **live 60/160 char counters**, optional image URL (falls back to the generated SVG art) |
| `/admin/categories` · `/admin/collections` | CRUD tables + create forms (name, auto-slug, description) |
| `/admin/orders` · `/admin/orders/[id]` | Status filter chips, line items, customer card, **status select** (pending → confirmed → ready_for_pickup → shipped → completed → cancelled) + internal note |
| `/admin/inquiries` · `/admin/inquiries/[id]` | Contact submissions, mark-handled toggle, detail view |
| `/admin/reviews` | Approve/unapprove, inline edit (author, rating, text, source, linked product), delete — this is where the owner syncs GBP reviews |
| `/admin/customers` | Profiles list (role, company, phone) with confirm-guarded promote/demote admin |
| `/admin/settings` | Social URLs (facebook/instagram/linkedin render in the footer **only when set**) + Google Business URL; homepage section editor (title/subtitle/body, active toggle, sort-order inputs) |

## Customer portal (`/account`)

Guarded by middleware (redirect → `/login?next=…`) **and** server-side re-checks; `/api/account/*` routes re-verify `auth.uid()`.

- **Overview** — profile summary card, recent orders, quick links.
- **Profile** (`/account/profile`) — edit full name, company, phone (upsert into `profiles`).
- **Orders** (`/account/orders`, `/account/orders/[id]`) — history with status badges, full detail with a visual status timeline, and a **Reorder** button that pushes the stored `orders.items` snapshot back into the cart.
- Guest/phone orders (`user_id null`) are intentionally not linked — the portal only shows rows owned by `auth.uid()` (enforced by RLS and a query-level filter).

## What's dynamic vs cached

- **Dynamic (per request):** all of `/admin/*`, `/account/*`, `/api/*`, auth pages/routes.
- **ISR 300s:** `/`, `/collections`, `/collections/[slug]`, `/products/[slug]` — built from Supabase at build/request time, cached for 5 minutes, `dynamicParams = true` so admin-added catalog entries appear without a rebuild. Mutations call `revalidatePath` on the affected pages.
- **Static:** about/contact/cart/login shells, `sitemap.xml`, `robots.txt`, `llms.txt`.

## Data model

- `collections` / `categories` / `products` — catalog. Products carry SEO columns: `meta_title`, `meta_description`, `long_description`, `faqs jsonb`. Anon select; admin write via `is_admin()`.
- `profiles` — 1:1 with `auth.users` (`full_name`, `company_name`, `phone`, `role admin|customer`). Auto-created by trigger on sign-up. Users select/update their own row; admins read/update all.
- `reviews` — `author_name`, `rating`, `text`, `source` ('google'), `is_approved`, nullable `product_id`. Anon reads approved only; admin manages.
- `orders` — `user_id uuid references auth.users (nullable)` + items jsonb, totals, `status` (pending → confirmed → ready_for_pickup → shipped → completed → cancelled, default `pending`), internal `note`, status timeline on the customer detail page. Authenticated users insert/select their own (`user_id = auth.uid()`); anon can insert phone orders with `user_id null`; admin all.
- `inquiries` — anon insert; admin read. `user_id` nullable.
- `site_settings` — key/value jsonb (seeded: `social_facebook`, `social_instagram`, `social_linkedin`, `google_business_url`). Footer renders social icons only when set.
- `homepage_sections` — admin-editable homepage content blocks (`section_key`, title, subtitle, body jsonb, `is_active`, `sort_order`).
- **Auth helpers**: `lib/supabase-server.ts` → `createSupabaseServer()`, `getUser()`; `lib/supabase-browser.ts` → `getSupabaseBrowser()`; middleware refreshes cookies and guards `/admin/*`, `/account/*` (redirect → `/login?next=…`).
- **Creating the first admin**: register at `/register`, then in the Supabase SQL editor run:
  ```sql
  update profiles set role = 'admin' where id = '<user-uuid>';
  ```

## Supabase setup

1. Create a project at [supabase.com](https://supabase.com).
2. SQL Editor → run `supabase/schema.sql`, then `supabase/seed.sql`.
3. Copy `.env.example` → `.env.local`, fill in project URL + **anon public** key.
4. Enable Email auth in Authentication → Providers (disable "Confirm email" if you want instant sign-in for testing).
5. Add the same env vars to Vercel.

## Reviews note

The 5 seeded reviews in `data/reviews.ts` are **real Google reviews captured during keyword/content research** (source: the business's Google Business Profile; aggregate 5.0 from 239 reviews). Manage and keep them synced with the live GBP from **/admin/reviews**.

## SEO program (implemented)

Per-page unique titles (≤60 chars, front-loaded) & 150–160 char descriptions · exactly one keyword-bearing H1 per page · canonical on every page (`metadataBase = https://www.greensolarworld.ca` — set `NEXT_PUBLIC_SITE_URL` to your real domain) · breadcrumbs (visual + `BreadcrumbList` JSON-LD) · JSON-LD: `["Organization","LocalBusiness"]` sitewide, `WebSite`+`SearchAction` sitewide, `Product` (brand/sku/offers/aggregateRating/reviews) + `FAQPage` + `BreadcrumbList` on product pages, `FAQPage` on home/collections · OG + Twitter cards sitewide · XML sitemap (auth pages excluded) · robots.txt (auth paths disallowed) · `/llms.txt` · keyword-mapped copy across home, collections (250–400 w intros + buying guides + FAQs) and 71 product pages (intro/Applications/Why-GSW/FAQs/specs).

## Design (Phase 4)

Bright, premium editorial B2B: `#FAFAF7` paper background, ink `#101828`, electric-amber `#FFC400` accent (deep amber `#92610A` for small text accents), warm-gray `#E8E6E1` borders, stock-green `#15803D`. Dark appears only in the amber CTA band's text buttons and the ink footer. Product photos render on white padded tiles; products without an honest photo match keep the generated SVG artwork. Real photos live in `public/images/` — every mapped file was visually inspected first; the full audit (what each cryptic/numbered file turned out to be, and which were rejected as spec sheets/diagrams) is in `data/image-notes.ts`. Product pages get a gallery (main + same-category verified views), and Product JSON-LD/og:image carry the absolute photo URL.
